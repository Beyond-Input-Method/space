# 常用语教程

## 1. 常用语是什么
常用语就是你自己维护的一份“小词库”。

比如你经常要输入：

- 公司全名
- 常用地址
- 固定回复
- 表情文本
- 一长串专业术语

你可以给这些内容配一个更短的编码，之后输入编码就能更快打出来。

## 2. 文件命名规则
当前方案会按下面顺序查找常用语文件：

1. `custom_phrase_<schema_id>.txt`
2. `custom_phrase.txt`

例如：

- `custom_phrase_double_pinyin_18.txt`
- `custom_phrase.txt`

如果用项目里的真实方案举例，常见的 `schema_id` 可能像这样：

- `double_pinyin_14`
- `double_pinyin_18`
- `double_pinyin_mspy_18`
- `pinyin_simp`
- `easy_en`

那么对应的文件名就可能是：

- `custom_phrase_double_pinyin_14.txt`
- `custom_phrase_double_pinyin_18.txt`
- `custom_phrase_double_pinyin_mspy_18.txt`
- `custom_phrase_pinyin_simp.txt`
- `custom_phrase_easy_en.txt`

含义可以理解成：

- `custom_phrase_<schema_id>.txt` 是“当前方案专用词库”
- `custom_phrase.txt` 是“当前方案的默认词库”

如果这两个文件都不存在，页面会提示你先启用 `custom_phrase` 补丁。

## 2.1 文件一般放在哪里
你可以先这样理解：

- 每个输入方案都有自己的目录
- 常用语文件要放在这个方案目录下面

当前项目的查找路径逻辑可以概括成：

```txt
${user_data_dir}/space/schemas/<当前方案目录>/custom_phrase_<schema_id>.txt
${user_data_dir}/space/schemas/<当前方案目录>/custom_phrase.txt
```

例如，如果当前方案目录就是 `double_pinyin_18`，那你看到的样子通常会接近这样：

```txt
.../space/schemas/double_pinyin_18/custom_phrase_double_pinyin_18.txt
```

或者：

```txt
.../space/schemas/double_pinyin_18/custom_phrase.txt
```

你不用死记完整绝对路径，重点只要记住三件事：

- 放到当前方案目录下面
- 文件名要符合命名规则
- 文件内容要符合 `词条 + Tab + 编码 + Tab + 权重`

## 3. 文件内容格式
常用语文件使用文本格式保存，推荐使用 **UTF-8** 编码。

每一条短语通常是一行，字段之间用 **Tab（制表符）** 分隔：

```txt
词条<Tab>编码<Tab>权重
```

例如：

```txt
北京大学\tbjdx\t100
谢谢老师\txxls\t80
我的邮箱是 123456@qq.com\twdyx\t60
```

你可以简单理解成：

- 第一列：真正要上屏的内容
- 第二列：你要输入的编码
- 第三列：优先级，数字越大通常越容易靠前

## 4. 命名和编码建议
为了后面自己也能看懂、记得住，建议这样写：

- 词条名称尽量直接、完整
- 编码尽量短，但不要和你常用编码严重冲突
- 同一类内容尽量采用同一种命名方式

例如：

- 地址类：`bjgs`、`shgs`
- 回复类：`hfnr`、`xxyy`
- 邮箱类：`wdyx`、`gzyx`

如果你把它想成给抽屉贴标签，就很好理解：

- 抽屉里的东西是“词条”
- 抽屉外面的标签是“编码”
- 标签越清楚，以后越容易找到

## 5. T9、T14、T18 的编码规则怎么理解
这里最重要的一点是：

**最终什么键会真的被当作编码输入，要看主题键盘里的 `click` 事件。**

也就是说：

- `schema` 里定义的是“编码映射规则”
- `theme` 里定义的是“你在屏幕上实际点到哪些键”
- 最终用户能输入什么，取决于这两者一起生效

下面是当前项目里这三种布局最常用的理解方式。

---

## 6. T9 编码规则
T9 的触发编码按数字键来理解，主要是：

```txt
1 2 3 4 5 6 7 8 9
```

对应的映射规则来自 `bim_t9.schema.yaml`：

```txt
abc -> 2
def -> 3
ghi -> 4
jkl -> 5
mno -> 6
pqrs -> 7
tuv -> 8
wxyz -> 9
```

你可以把它理解成老式手机九宫格：

- `a / b / c` 这一组，都会落到 `2`
- `d / e / f` 这一组，都会落到 `3`
- 以此类推

所以 T9 常用语编码，通常应该写成数字串，例如：

```txt
北京\t245446\t100
```

在主题 `resources/space/themes/t9/theme.yaml` 里，实际可点击的主键也是数字键：

- `1`
- `2`
- `3`
- `4`
- `5`
- `6`
- `7`
- `8`
- `9`

所以 T9 下最稳妥的做法就是：

- **编码直接写数字**
- 不要按全键盘字母去理解

---

## 7. T14 编码规则
T14 的规则可以理解为 14 键压缩布局，常用触发键是：

```txt
q e t u o a d g j z c b
```

这是因为 `bim_t14.schema.yaml` 里把字母做了合并，例如：

- `q / w -> q`
- `e / r -> e`
- `t / y -> t`
- `u / i -> u`
- `o / p -> o`
- `a / s -> a`
- `d / f -> d`
- `g / h -> g`
- `j / k -> j`
- `z / x -> z`
- `c / v -> c`
- `b / n -> b`

主题 `resources/space/themes/t14/theme.yaml` 里，主键 `click` 也正是这些键：

```txt
q e t u o a d g j l z c b m
```

其中真正承载压缩字母组的主编码键，重点可以记成：

```txt
q e t u o a d g j z c b
```

额外的：

- `l` 往往单独存在
- `m` 更多承担标点/功能扩展角色，但主题里也有独立点击键

所以 T14 下写常用语时，最稳妥的理解是：

- 编码尽量使用压缩后的主键字母
- 不要再按完整 26 键逐字母想象

例如：

```txt
老师好\tldgh\t100
```

这里的每个字母，都应该优先按照 T14 的压缩键位去记忆。

---

## 8. T18 编码规则
T18 的规则可以理解为 18 键双拼压缩布局。你现在最常接触到的主键是：

```txt
q w r y u i p a s f h j l z x v b m
```

`double_pinyin_18.schema.yaml` 里配置了派生规则，例如：

- `e -> w`
- `t -> r`
- `o -> i`
- `d -> s`
- `g -> f`
- `k -> j`
- `c -> x`
- `n -> b`

这意味着一部分字母会折叠到另一部分主键上。

而在主题 `resources/space/themes/t18/theme.yaml` 里，真正可点击的主键 `click` 是：

```txt
q w r y u i p a s f h j l z x v b m
```

所以 T18 下的编码建议就是：

- 优先使用这 18 个主键来写编码
- 把被折叠的字母理解为“也归到这些主键里”

例如：

- `e` 相关输入，记到 `w`
- `t` 相关输入，记到 `r`
- `o` 相关输入，记到 `i`
- `d` 相关输入，记到 `s`
- `g` 相关输入，记到 `f`
- `k` 相关输入，记到 `j`
- `c` 相关输入，记到 `x`
- `n` 相关输入，记到 `b`

如果你把 T18 想成“把 26 个字母收纳到 18 个主键里”，就比较容易理解。

---

## 9. 什么时候以主题为准
如果你看到：

- schema 里是映射规则
- theme 里是键盘按钮定义

那你在实际录入常用语编码时，**优先以主题里能真实点到的 `click` 键为准**。

原因很简单：

- schema 决定“某些字母最后归并到哪个键”
- theme 决定“界面上到底给你哪些键可点”

因此教程里提到的：

- T9：数字键 `1-9`
- T14：`q e t u o a d g j z c b` 为主
- T18：`q w r y u i p a s f h j l z x v b m`

本质上都是为了帮助你更贴近真实键盘来写编码。

## 10. 新手最简单的使用建议
如果你刚开始用，建议这样做：

- T9：直接写数字编码
- T14：只用主压缩键写编码
- T18：只用 18 个主键写编码
- 先少量添加几条，测试能否顺利触发
- 觉得好用后，再批量整理自己的短语库

## 11. 一个简单示例
比如你常输入“谢谢老师”，你可以这样配置：

```txt
谢谢老师\txxls\t100
```

如果你切到 T9，就更适合改成数字风格；如果切到 T14 / T18，就更适合改成对应布局下容易按到的主键编码。

## 12. 看不懂时怎么排查
如果你发现某条短语怎么都打不出来，可以按这个顺序检查：

1. 当前方案有没有启用 `custom_phrase` 补丁
2. 常用语文件有没有放在当前方案目录里
3. 文件名是不是 `custom_phrase_<schema_id>.txt` 或 `custom_phrase.txt`
4. 每一行是不是用了 **Tab** 分隔
5. 当前用的是 T9、T14 还是 T18
6. 你写的编码，是否真的对应当前主题里可以点击的主键

只要按这个顺序排查，大多数问题都能很快找到原因。

## 13. 如果提示“当前方案缺少常用语文件”怎么办
你可以把这个提示理解成：

- 当前方案目录里，还没有找到可以用的常用语文件
- 系统现在不知道该从哪一份短语表里读取内容

这时候按下面步骤处理就可以：

1. 先确认当前方案已经启用了 `custom_phrase` 补丁
2. 打开当前方案对应的用户目录
3. 在该目录里准备下面两个文件名中的一个：
   - `custom_phrase_<schema_id>.txt`
   - `custom_phrase.txt`
4. 文件内容先只写 1 到 2 条测试数据
5. 保存时使用 **UTF-8** 编码
6. 回到常用语页面重新进入，或重新触发加载

如果你不知道当前方案对应哪个文件名，可以先对照下面这种思路：

- 当前方案是 `double_pinyin_18`
  - 优先尝试：`custom_phrase_double_pinyin_18.txt`
- 当前方案是 `double_pinyin_14`
  - 优先尝试：`custom_phrase_double_pinyin_14.txt`
- 当前方案是 `pinyin_simp`
  - 优先尝试：`custom_phrase_pinyin_simp.txt`

如果你暂时拿不准 `schema_id`，那就可以先放一个更通用的：

- `custom_phrase.txt`

如果你不知道该写什么，可以先抄这个最小示例：

```txt
谢谢\txxls\t100
北京\tbj\t80
```

如果这样还不行，再继续检查：

- 文件名有没有写对
- 字段之间是不是 **Tab**，不是空格
- 当前方案是不是你正在实际使用的那个方案
- 编码是不是符合当前 T9、T14 或 T18 的键位规则

你也可以把它想成“给当前输入方案放一本专用通讯录”：

- 文件放对位置，系统才能找到
- 文件名写对，系统才知道该读哪一本
- 内容格式写对，系统才看得懂里面的每一条记录
